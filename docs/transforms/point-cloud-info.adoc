[[point-cloud-info]]
= Point Cloud Info
:plugin-id: SOGIS_POINTCLOUD_INFO
:plugin-type: transform
:description: Adds point cloud metadata such as point count, bounds, CRS and dimensions.

The Point Cloud Info transform reads the schema of a Point Cloud value and adds the selected
metadata as ordinary Hop fields. It never executes the pipeline and never reads points.

== Description

The schema of a Point Cloud value is available directly after the Point Cloud Reader, because the
reader describes the source header. All values are planning values: bounds and point count describe
the source (or the last planned filter that changed them), not a materialized result.

Available information fields:

[cols="1,3",options="header"]
|===
|Field |Value

|`point_count`
|Number of points reported by the reader, empty when unknown.

|`bounds`
|`minX,minY,minZ,maxX,maxY,maxZ` as text.

|`minx`, `miny`, `minz`, `maxx`, `maxy`, `maxz`
|Single bounds coordinate as number.

|`crs`
|Authority code (for example `EPSG:2056`) or WKT when no authority exists.

|`dimensions`
|Comma separated dimension names with their storage types.
|===

== Input

A field with the Hop type `Point Cloud`, usually produced by the Point Cloud Reader.

== Options

[cols="1,3,1",options="header"]
|===
|Option |Description |Default

|Point Cloud field
|Name of the input field.
|`pointcloud`

|Information fields
|Comma separated list of the metadata fields to add.
|`point_count,bounds,crs,dimensions`

|Field prefix
|Prefix for the added field names.
|(empty)
|===

== Output

The input row plus one field per selected information entry. The Point Cloud value itself is passed
through.

== Supported engines

This transform runs on the Hop local engine and does not need native access, because it works on
the value model only.

== Examples

* `examples/04-info.hpl` adds point count, bounds, CRS and dimensions of a source.

== Error handling

Enable error handling to route rows with missing or unknown metadata to an error transform.

== Limitations

The information reflects the planned pipeline, not executed statistics. Use dedicated statistics
transforms (planned) when exact counts or distributions are required.
